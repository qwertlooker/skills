# 文档与脚本风格指南

目标：让使用者尽快判断是否适用，复制一条明确路径跑通，再按需查看评测和排障。当前目标仓模板有明确要求时遵循；其他情况下用下列默认结构。已有文档只改受影响部分，不为统一标题重写有效说明。

## README 的阅读顺序

| 位置 | 使用者要知道什么 | 推荐写法 |
|---|---|---|
| 标题、概述与使用范围 | 这是什么模型，能做什么，是否适用 | `# <ModelName> 推理指导`；简述任务、准确变体和适配路线，模型来源就近链接；先说明已验证范围和限制 |
| 环境准备 | 我的设备和软件是否匹配 | 一张配套版本表：实测硬件、CANN、Python、框架及路线必要工具。安装命令统一放下一节 |
| 快速上手 | 怎样得到第一个可检查的结果 | 源码/依赖 → 权重与最小输入 → 必要转换 → 一次推理；每步给真实命令和产物位置 |
| 精度与性能 | 怎样复现，结果意味着什么 | 单独给正式数据准备/评测命令，再给精度表、性能表与必要口径；和单样例路径分开 |
| 常见问题（按需） | 遇到已知问题如何处理 | 仅放实际问题、适用版本和简短解决方法；不重复前面的限制，没有问题就省略 |
| 参考来源（按需） | 需要查哪些原始资料 | 链接优先放首次使用处；目标仓要求公网地址清单时集中列一次，不重复链接表 |

输入输出简单时在概述用两行说清；张量、多模态或多组件模型按需增加输入输出表。文件布局会影响操作时才增加紧凑目录树，区分候选自带、下载得到和运行生成。目标仓要求独立“输入输出数据”“文件目录”章节时将相应内容独立成节，不再重复。

## 快速上手只保留一条默认路径

- 开始写明执行目录和需要用户替换的少量路径；后续命令保持同一基准。切换目录要明确，不假设读者记得上一个 shell 的状态。
- 单样例优先使用可获取的真实小输入；完整评测数据在评测处准备。若运行本身必须下载整包，提前说明授权、体积和目录要求。
- 环境表只写版本和兼容范围；容器启动、依赖安装、patch 等命令按实际执行顺序出现一次。已有配套环境可跳过环境创建。
- 有必要转换才写 ONNX/ATC/OM 步骤；在线 PyTorch/TorchAir/vLLM 不出现无关命令。server/client 场景写清启动、就绪判断与一次请求。
- 命令块可顺序复制：`python3`、真实脚本/参数、固定 revision、明确输入输出，和当前 `--help` 一致。权重/数据用可核验来源，受限下载给可执行离线替代；安装不能覆盖已配套框架。
- 选卡在环境设置处单独配置可见设备变量；基础命令表达设备类型，不在每条命令前重复固定卡号。
- 每块关键命令后给一行成功判据，例如“生成 outputs/result.json，包含 text 和 device”。只展示必要输出片段，不贴完整启动日志或设备状态屏幕。
- 只解释示例中需用户决定或含义不直观的参数。完整参数交给 `--help`；其他任务只写差异参数或独立短例，不复制整套安装和下载流程。

## 评测清楚，说明简短

- 单样例证明能运行；正式指标单独说明 dataset/split、规模、权重和关键预后处理。不同任务分别给命令及 manifest，不能用“全部评测”掩盖数据差异。
- 首次出现 manifest 时说明它是评测样本清单，给出实际生成路径及必要字段。评测命令后说明在哪个文件查看实际样本数、指标及通过/不通过判定；有通过线时写明依据，只有成功退出不能说明精度达标。
- 先给评测命令及输出位置，再给结果。精度表保留指标、NPU 结果、可比公开基线和来源；性能表保留实测设备、batch/并发、延迟或吞吐及单位。条件相同时表前说明一次，不逐行重复。
- 紧邻结果交代 dtype、输入规模、计时边界、warmup、独立运行次数与统计方式；同配置已在命令中明确的值不再展开成长段。首次编译、稳态和端到端含义有差异时分别标明。
- 只保留帮助理解结论的差异和限制，复杂对齐分析与排障留内部记录。不能为了简短删掉未实测声明、CPU fallback、样本不足或不可比条件。
- 同一命令、路径或条件只完整定义一次，其他处用章节链接。避免“快速上手概要 + 后文同一套详细步骤”；流程较长时用目录导航，不复制流程。
- 入口支持断点续跑时，说明复用哪个结果目录、如何启动及汇总是否覆盖完整声明集合。源码、权重或数据改变后，先核实旧结果能否复用，不能直接沿用原目录续跑。

## 脚本也按使用者视角组织

- 一个清楚的入口完成一个可独立执行的任务；复用官方入口、evaluator 和 helper，不为目录整齐新造 wrapper 或复制逻辑。参数沿用工程约定，路径可配置，默认值可在他人环境使用。
- 帮助文本交代必填参数、实际默认值、输入格式和输出；成功打印结果摘要与产物位置，失败给具体原因并非零退出。wrapper 传播子进程错误，不能失败后仍报成功。
- 必需依赖在实际执行前导入并严格失败，保留原始错误；设备注册按选择条件导入。可将重型运行依赖放在参数解析后，使 `--help` 无需权重、设备或无关后端；不能用假实现掩盖缺包。
- 正常日志简洁，保留任务、实际样本数、真实设备和结果；失败保留定位信息，不暴露凭据，不刷重复请求或签名长 URL。详细日志另存，README 只展示必要片段。
- 先解析路径再切换 cwd；下载/解压/离线复用与模型执行分开。官方字段或关键权重缺失明确失败；兼容分支有版本依据，不添加静默替代或宽泛吞错。
- 修改保持最小；按项目 lint 清理未用 import、拼写和调试残留，未经明确允许不加检查屏蔽。patch 应用和恢复方式见 `patch-modification-patterns.md`。

## 写完的最后一遍

从新使用者视角只走文档默认路径：需要准备什么、从哪里执行、哪条命令、应生成什么、哪里看正式结果？删掉不帮助回答这些问题的重复文字。一个一级标题、连续层级、路径和参数大小写准确；不留空章节或“暂无问题”等填充句。

信息公开范围见 `output-contract.md`；技术证据与通过条件见 `validation-contract.md`；交付和只读检视共用 `modelzoo-delivery.md`。风格选择不另加一套验收门禁。

提炼依据见 `modelzoo-sampling.md`；不照搬样本的版本、默认卡号或技术结论。
