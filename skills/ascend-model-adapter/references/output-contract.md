# 用户交付与信息边界契约

## README 的读者和用途

读者是需要安装、运行或评测模型的使用者。README 应自包含，并提供复现所需版本、命令、输入输出和有依据的结果。章节名称可跟随项目惯例。

本契约只规定信息归属与交付内容；标题、章节、命令和脚本组织在 `style-guide.md` 统一维护，ModelZoo 特定风格仅在上库任务适用。

写每段前判断：此内容是否帮助使用者安装、运行、评测、解释结果或理解限制？执行进度、内部验收和排障过程写入项目内部记录。

## 信息归属

| 信息 | 内部记录/对话报告 | README |
|---|---|---|
| 技术等级、target_ready、门禁和提交进度 | 记录 | 不出现 |
| agent 计划、待办、下一步补验、失败尝试 | 记录 | 不出现 |
| 证据 ID、私有日志、账号、内部路径 | 记录 | 不出现 |
| 固定源码、权重、config/tokenizer、license | 保存来源/哈希 | 公开复现所需信息 |
| 实测环境、数据集、指标、性能口径 | 保存原始证据 | 公开真实结果和条件 |
| 已知限制、未验证能力、CPU fallback | 保存原因与补验计划 | 公开对使用者的影响 |
| 当前仍需的 workaround | 保存完整排障 | 提炼准确的操作与适用版本 |

README 公布的版本、命令、指标和限制必须与有效证据一致。此要求不包含内部状态、计划或全部记录的内容同步。

## 公开事实的表达

内部记录：`status=S2; target_ready=false; 无 NPU，精度与性能门禁未执行。`

README：`已完成 CPU 功能测试，尚未在 Ascend NPU 上实测。NPU 精度与性能结果暂未提供。`

内部记录：`S3 已通过，等待 clean-room 和目标仓审计。`

README：给出实际 NPU 硬件、软件版本、数据集/split、指标、命令和计时条件；不附上库进度。

内部记录：`第三次尝试修改音频加载器后测试成功，下一步整理环境。`

README：仅在仍影响使用者时说明音频依赖版本、加载方法及限制；不复制尝试历史。

`S3` 也可能是模型名称或存储服务。按内容语义区分，不能全局删除词语。未知结果不填理论值，不写“通过”占位，也不能删掉验证范围来营造完整性。

## 按任务覆盖用户所需信息

- 模型用途、上游固定 revision、权重/config/tokenizer/label map 与 license。
- 实测硬件、镜像/CANN/Python、框架及路线工具版本；未测试的兼容范围如实注明。
- 环境启动、依赖安装、源码和 patch 应用。命令中的工作目录与路径明确，不重装镜像配套核心栈。
- 数据、权重、evaluator、protocol/label 的来源、目录树与生成方法；离线模式缺文件时严格失败。
- 实际路线的导出/转换、推理或 server/client 命令，输入输出 contract 和结果路径。
- 有证据的精度/性能、对照来源与比较条件；性能计时和重复要求按 `validation-contract.md`，不展示本地 CPU 性能来推断加速比。
- 已知限制、实际 workaround 与 FAQ；公开可复现的结果输出路径可以出现，开发期私有日志路径不出现。

缺失的安装或运行方法须明确说明交付物不能直接执行，不能发布看似可用的占位命令。正式目标仓要求完整实测时，缺口使候选不满足验收条件；不能用文字声明代替验证。

## 文件边界

- 正式候选只含明确列出的运行、评测、说明及目标仓要求的文件；README 不依赖被排除的内部文件。
- `.ascend-adaptation/`、`worklog.json`、`NPU_ADAPTATION.md`、`ACCEPTANCE_PLAN.md`、公开事实草稿、证据映射、候选清单和打包报告保留在候选外。
- 开发 checkout、cache、权重、数据和大日志默认不分发；必要的小 fixture 显式列入清单。用户确实要求交付验证报告时，作为单独产物处理。
- 保留已有有效 README 和 `README_old.md`，除非用户要求迁移或删除；迁移内容按读者用途分类。

## 内容审阅与工具边界

先按 [内容审阅](content-review.md) 逐段核实文档和实现，再用 `delivery.py check` 扫描明确的流程字段、内部文件与引用；需要候选时用 `assemble` 收集逐文件清单和哈希，并按交付工作流重放。内容审阅、自动检查和运行验证各自报告结论。

脚本不执行 NPU 测试，也不能发现所有自然语言改写或任意私有路径。通过内容检查不代表工程验收通过。
