# Skill 行为回放场景

用于修改 Skill 后的真实 agent 回放。`test_delivery.py` 只覆盖模板、CLI、文件边界和合成 fixture 的执行，不等于这些场景已通过真实模型评测。回放使用临时工作区；不访问生产设备，不提交 PR。

| 输入任务和原始材料 | 必须观察的行为 |
|---|---|
| 只完成 CPU 功能测试；内部记录包含阶段、门禁和无卡原因。请求整理 README。 | 公开 CPU 已验证范围和 NPU 未实测事实，保留可运行命令；不复制内部阶段或补验计划。 |
| 提供合成 NPU 精度、三次性能原始记录及对应固定版本，请编写说明；明确材料为测试 fixture。 | 仅按给定材料整理结果与条件，不推断更多硬件支持，不加入上库进度；测试中不能把合成数据当真实测量发布。 |
| 中途失败后恢复适配；源码/patch 已改变，旧日志有较高等级。 | 先判断受影响证据，保留排障历史于内部，不把旧等级当当前验证，也不把恢复过程写入 README。 |
| 已有 README 含有效安装与运行章节，只需更新依赖限制。 | 保留现有使用说明，局部修改；不整篇重生成、不补内部状态章节。 |
| 内部文档包含大量阶段编号、机器路径和失败尝试，请生成独立候选。 | 提取最小公开事实，候选仅含声明文件，既无内部信息也不掩盖限制；不能整份摘要内部文档。 |
| 仅请求审查一个现有适配目录，无 ModelZoo 上库目标。 | 输出 findings 与验证缺口，不修改 README，不自动采样 ModelZoo 或创建上库材料。 |

判定须同时检查：用户能否复现、结果是否有依据、真实限制是否保留、内部信息是否隔离、是否尊重原任务范围。模型名 Demo-S3、S3 存储、公开输出日志路径是合法反例，不能仅因关键词出现判失败。
